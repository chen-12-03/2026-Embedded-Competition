# 基于 RV1126 的原材料智能分拣与设备监测系统需求文档

## 1. 项目背景

本作品面向瑞芯微赛题“选题方向三：智慧工业应用”，使用 `RV1126` 开发板构建一套生产端原材料分拣设备。

业务场景如下：

- 买家向厂家提供原材料用于生产
- 买家侧为原材料绑定订单信息，并通过 `NFC` 关联物料身份
- 厂家侧在使用原材料前，通过传送带输送物料
- 系统读取 `NFC` 中的物料 ID，并查询局域网 Web 服务中的订单参数
- 系统通过摄像头对物料进行视觉识别
- 系统将 `Web 订单参数`、`NFC 关联结果`、`视觉识别结果` 进行比对
- 一致则放行，不一致则报警并分拣到异常区
- 同时系统对传送带设备本身进行 `振动`、`电流` 等健康监测

本系统首版重点展示“订单录入 -> 物料身份绑定 -> 板端读卡 -> 视觉识别 -> 自动分拣 -> 实时监控 -> 异常告警”的完整闭环。

## 2. 建设目标

系统需要实现以下目标：

- 对进入产线的物料进行身份识别和一致性校验
- 对异常物料进行自动分拣
- 对设备运行状态进行实时监测和告警
- 提供局域网内可访问的实时监控页面
- 提供买家侧订单录入入口
- 提供设备端本地调试与控制界面

## 3. 系统总体架构

首版系统采用 `局域网一体化部署` 架构：

- `RV1126` 开发板同时承担：
  - 设备控制
  - 视觉识别
  - NFC 读卡处理
  - Web 服务
  - 局域网数据服务
- `买家端` 通过手机浏览器访问移动端页面，录入订单信息
- `产线监控端` 通过浏览器访问实时监控页面
- 后续公网访问能力作为扩展项保留，不属于首版必做范围

## 4. 业务角色

### 4.1 买家端

负责模拟下单和物料参数录入。

首版职责：

- 新建订单
- 录入单一物料参数
- 为物料生成唯一 `物料ID`
- 可选地参与 `NFC` 写卡流程

说明：

- 首版默认使用 `Android` 手机作为可能的 NFC 写卡终端
- 但 `手机写 NFC` 不是首版核心验收项
- 首版允许采用 `预写卡` 或其他方式预先写入物料 ID

### 4.2 产线监控端

负责查看设备实时状态与处理告警。

首版职责：

- 查看实时画面
- 查看当前检测物料信息
- 查看视觉识别结果
- 查看最终判定结果
- 查看设备健康状态
- 查看历史记录
- 执行启动、停止、复位等控制操作

### 4.3 设备端

负责实际执行检测、分拣与设备自监测。

## 5. 物料范围

首版支持的演示物料限定为：

- 材质统一为 `木头/木质件`
- 形状限定为 `正方形 / 长方形 / 三角形`
- 颜色限定为 `黄色 / 蓝色 / 绿色 / 红色`

其中视觉分类优先采用“颜色 + 形状”的联合标签形式，例如：

- 红色三角形
- 蓝色正方形
- 黄色长方形

但在数据存储层，订单参数采用拆字段方式保存，而不是直接保存单一组合标签。

## 6. 订单与数据模型

### 6.1 首版订单模型

首版采用 `一单一物料` 模型，即一条订单对应一个物料。

### 6.2 首版最小字段集

必填字段：

- `物料ID`
- `物料类型`
- `颜色`
- `形状`

扩展字段：

- `材质`
- `尺寸`
- `批次`
- `备注`

说明：

- 首版 `物料类型` 建议统一保存为 `木质件`
- 前端录单时可不让用户手填 `物料类型`，由系统自动补全
- 首版 `材质` 可固定记录为 `木头`
- 首版 `颜色` 受控枚举固定为 `黄 / 蓝 / 绿 / 红`
- 首版 `形状` 受控枚举固定为 `正方形 / 长方形 / 三角形`

## 7. NFC 需求

### 7.1 NFC 存储内容

首版 `NFC` 仅存储：

- `物料ID`

订单详细参数不写入 NFC，而是由系统读取 `物料ID` 后到 Web/数据库中查询。

### 7.2 NFC 标签位置

首版建议优先将 `NFC` 标签贴在以下位置：

- 物料外包装
- 载具
- 固定附着面

若物料本体表面条件合适，也允许直接贴在物料本体。

### 7.3 NFC 读卡流程

产线采用前后分工位流程：

1. 前工位读取 `NFC`
2. 后工位执行视觉检测和异常分拣

### 7.4 NFC 异常处理

当出现以下情况时，直接判定为 `检测异常`：

- 无标签
- 读卡失败

对应物料需进入异常分拣流程。

## 8. 视觉识别需求

### 8.1 视觉目标

首版视觉模块目标：

- 以 `AI 部署` 为优先方案
- 首版以 `物料分类/属性分类` 为主
- 先保证可区分“颜色 + 形状”

首版不强制实现：

- 复杂缺陷检测
- 破损检测
- 高级异常检测

这些内容作为后续增强项保留。

### 8.2 视觉实现策略

首选方案：

- 部署 AI 模型进行分类识别

备选方案：

- 若 AI 效果不理想，可退回传统规则识别
- 对于当前受控样品，允许直接采用 `传统视觉规则 + 可替换 AI 接口` 作为首版落地方案

因此需求上要求：

- 视觉算法应具备可替换性

### 8.3 视觉环境约束

为提高识别稳定性，首版应尽量满足以下条件：

- 固定机位
- 固定背景
- 可加补光

### 8.4 视觉结果输出

视觉结果应尽量映射为结构化字段，例如：

- `物料类型`
- `颜色`
- `形状`

然后与 Web 订单字段进行逐项比对。

### 8.5 置信度策略

视觉识别应支持 `置信度阈值配置`，但具体阈值不在本需求文档中写死，由后续联调确定。

### 8.6 视觉失败处理

当出现以下情况时，系统进入 `待人工处理`：

- 拍照成功但无法给出可靠识别结果
- 识别置信度低于阈值

此类情况不直接归入“检测异常”。

## 9. 一致性比对规则

### 9.1 基本原则

系统需要对以下三方信息进行关联和校验：

- `NFC` 读取到的 `物料ID`
- `Web/订单库` 中该 `物料ID` 对应的订单参数
- `视觉识别结果`

### 9.2 当前已确定规则

- 只要出现不一致，系统必须 `报异常`
- 放行条件当前仍待最终确认

当前候选放行逻辑：

- `三者全一致` 才放行
- 或至少 `视觉结果与 Web 订单一致` 才放行

### 9.3 首版建议

为保证逻辑清晰，建议首版优先采用：

- `视觉结果与 Web 订单字段逐项一致` 才允许放行

由于 `NFC` 首版仅保存 `物料ID`，其作用主要是身份索引，不参与属性值比对。

该条可在后续联调阶段再最终确认。

## 10. 订单状态流转

首版订单状态至少包含：

- `已创建`
- `已检测通过`
- `检测异常`
- `待人工处理`

状态含义如下：

- `已创建`：买家端已录入，但尚未完成检测
- `已检测通过`：系统已完成检测，且物料放行
- `检测异常`：系统已完成自动判定，确认存在异常
- `待人工处理`：系统无法完成自动判定，需要人工介入

### 10.1 待人工处理场景

包括但不限于：

- 查无订单
- 网络异常
- 服务异常
- 视觉识别失败
- 重复读到已完成状态的 `物料ID`

### 10.2 已通过后的重复使用

当某个 `物料ID` 已经完成检测通过后：

- 不允许再次作为有效待检物料重复使用
- 若再次读到该 `物料ID`，系统进入 `待人工处理`

## 11. 产线机械流程

### 11.1 总体结构

首版采用：

- 单条传送带
- 单方向输送
- 正常区和侧边异常区两类收集区

### 11.2 分拣方式

异常件或待检件通过 `舵机/挡板机构` 拨到侧边收集区。

正常件则默认继续沿主线前进，最终进入正常收集区。

### 11.3 工位流程

建议工位顺序如下：

1. 读卡工位
2. 视觉检测工位
3. 分拣工位

### 11.4 分拣控制时序

首版可采用以下联合策略控制拨料时机：

- 到位传感器
- 传送带运行时间估算

### 11.5 正常件处理

首版不强制要求对正常件进行二次到位确认，只要默认其沿主线继续前行即可。

## 12. 运行模式

系统应支持两种运行模式：

- `单件节拍模式`
- `连续上料模式`

说明：

- 单件模式要求优先实现稳定
- 连续模式作为增强能力实现
- 两种模式应支持切换

为支撑连续模式，系统允许增加：

- 光电
- 红外对射
- 其他到位检测传感器

用于判断物料是否到达：

- NFC 区
- 拍照区
- 分拣区

## 13. 设备健康监测需求

### 13.1 监测目标

振动、电流采样的主要目的不是判断物料质量，而是监测：

- 传送带电机
- 传动机构

是否处于正常运行状态。

### 13.2 状态分级

设备健康监测采用三级状态：

- `绿色`：正常
- `黄色`：轻微异常
- `红色`：严重异常

### 13.3 状态行为

- `绿色`：正常运行
- `黄色`：继续运行，但在 Web/设备端告警
- `红色`：告警并自动停机保护

### 13.4 恢复方式

黄色和红色异常都不自动恢复。

必须由人工通过以下入口之一复位：

- Web 端
- 设备端

## 14. 启停与保护逻辑

### 14.1 上电默认状态

设备上电后默认进入：

- `待机`

必须由人工明确发出开始指令后才进入运行态。

### 14.2 启动前自检

启动前必须执行自检，至少覆盖：

- 摄像头在线状态
- NFC 模块状态
- 传送带驱动状态
- 舵机控制状态
- 网络/服务连通状态

### 14.3 自检失败处理

- 自检失败时禁止进入运行态
- 必须显示具体失败原因
- 支持人工修复后重新执行自检
- 仅当全部通过后才允许启动

### 14.4 正常停止逻辑

在没有严重告警时，点击停止后系统应：

- 先处理完当前物料
- 再停止整机

### 14.5 严重告警停机逻辑

当出现红色严重告警时：

- 系统应立即停机

若此时传送带上仍有物料，首版由人工处理，不要求自动清料。

## 15. 异常分类与优先级

### 15.1 异常展示要求

系统出现异常时，Web 端和设备端都必须显示：

- 明确的异常原因

例如：

- 查无订单
- 读卡失败
- 无标签
- 形状不一致
- 颜色不一致
- 视觉识别失败
- 设备电流异常
- 设备振动异常
- 物料ID重复/已处理

### 15.2 多异常并存要求

当一件物料同时命中多个异常原因时：

- 应列出所有命中的异常原因
- 应突出显示最高优先级异常

### 15.3 当前异常优先级

首版暂定优先级如下：

1. `设备红色故障`
2. `查无订单/查单失败`
3. `视觉识别失败`
4. `形状不一致`
5. `颜色不一致`
6. `设备黄色告警`

## 16. 人工处理逻辑

### 16.1 待人工处理物料去向

首版允许将 `待人工处理` 物料与 `检测异常` 物料统一拨入侧边收集区。

### 16.2 人工处理后的回流

首版不实现自动回流或重新进入主线。

即：

- 异常件/待检件进入侧边区后不自动返回
- 若后续需要复检，由人工重新上料

人工复检作为扩展项保留。

## 17. Web 功能需求

### 17.1 监控端主功能

Web 监控端至少应具备：

- 实时设备状态显示
- 当前检测物料信息显示
- 当前订单参数显示
- 当前视觉识别结果显示
- 最终判定结果显示
- 异常告警显示
- 设备健康状态显示
- 实时视频预览
- 历史记录查看
- 启动/停止/复位控制

### 17.2 实时视频能力

首版只要求：

- 查看摄像头实时预览画面

不强制实现：

- 回放
- 暂停当前帧

### 17.3 历史记录能力

Web 历史记录按 `单件物料` 保存。

每条历史记录至少应包含：

- `物料ID`
- 检测时间
- 订单参数摘要
- 视觉识别结果摘要
- 最终判定结果
- 异常原因
- 设备健康状态摘要

同时支持关联：

- 现场抓拍图片

说明：

- 若首版存储资源有限，可优先对异常件保存图片

### 17.4 用户角色

首版 Web 仅考虑：

- 单一操作员角色

不实现复杂权限系统。

## 18. 买家端功能需求

首版买家端为移动端 Web 页面。

至少应具备：

- 新建订单
- 录入物料 ID
- 录入颜色
- 录入形状
- 系统自动补全固定物料类型 `木质件`

暂不要求实现：

- 复杂订单修改流程
- 删除流程
- 审核流程
- 多角色权限

说明：

- 未来可升级为原生手机 App
- 但首版不强制

## 19. 设备端本地界面需求

### 19.1 硬件形式

设备端优先考虑：

- 触摸屏

若硬件受限，也允许降级为：

- 显示屏 + 按键

### 19.2 本地界面职责

设备端本地界面至少应支持：

- 显示当前运行状态
- 显示当前物料检测结果
- 显示设备健康状态
- 执行人工复位
- 启动设备
- 停止设备
- 切换运行模式
- 手动测试舵机
- 手动测试传送带

说明：

- 历史记录查询不要求在设备端实现
- 历史记录统一以 Web 端为主

## 20. 首版范围定义

### 20.1 首版必须实现

- RV1126 板端运行主流程
- 订单录入
- NFC 读卡
- 根据物料 ID 查订单
- 摄像头采集
- 物料颜色/形状分类
- 字段级比对
- 正常放行
- 异常拨料
- Web 实时监控
- 设备健康监测
- 启动前自检
- 红黄绿状态告警
- 历史记录
- 本地小屏调试

### 20.2 首版可降级实现

- 手机直接写 NFC
- 连续上料模式的完整稳定版本
- 异常件图片全量保存
- 触摸屏交互的完整 UI 细节

### 20.3 后续扩展项

- 公网访问能力
- 原生手机 App
- Web 或专用模块写 NFC
- 多物料/一单多件模型
- 更丰富的字段比对
- 缺陷检测
- 自动回流复检
- 正常件到位确认
- 自动清料
- 远程升级/在线更新

## 21. 当前待定项

以下内容目前仍为待定，后续需结合样品、算法效果和机械实现再确认：

- 最终放行逻辑是“严格三方一致”还是“视觉与 Web 一致即可”
- 红/黄/蓝/绿的最终 HSV 阈值范围
- 是否必须现场演示手机写 NFC
- 视觉模型具体方案
- 颜色识别是直接输出标准颜色还是先做颜色值映射
- 形状识别是否采用固定 ROI 或轮廓自动定位
- 实时监控首页具体 UI 布局
- 人工处理场景下，单向传送带是“暂停等待”还是“直接拨入侧边待检区”的更细策略
- 设备端最终采用触摸屏还是显示屏加按键

## 22. 开发建议

为降低比赛实现风险，建议按以下顺序推进：

1. 跑通局域网 Web 服务与订单录入
2. 跑通 NFC 读卡与物料 ID 查单
3. 搭建固定光照下的视觉采集环境
4. 实现首版颜色 + 形状分类
5. 实现字段级比对与异常原因输出
6. 实现舵机拨料与传送带控制
7. 实现电流/振动采样与红黄绿告警
8. 补齐小屏调试和历史记录展示
